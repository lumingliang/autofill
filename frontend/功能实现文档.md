## 四、核心功能实现

### 4.1 路由系统

**文件**: `src/router/index.ts`

- 使用 Vue Router 4 的 `createRouter` 和 `createWebHistory`
- 动态路由加载：登录后从后端获取菜单数据，动态生成路由
- 路由守卫：
  - 未登录用户重定向到登录页
  - 已登录用户访问登录页重定向到首页
  - 动态加载用户菜单和权限

**静态路由** (`src/router/routes.ts`):
- `/login` - 登录页
- `/404` - 页面未找到
- `/403` - 无权限

**动态路由**: 从后端 `/base/usermenu` 获取菜单数据，构建为 `Layout` 布局下的子路由

### 4.2 状态管理

使用 Pinia 管理全局状态，分为四个模块：

#### 4.2.1 App Store (`src/store/modules/app.ts`)
- `collapsed`: 侧边栏折叠状态
- `isDark`: 深色模式（使用 `@vueuse/core` 的 `useDark`）
- `reloadFlag`: 页面刷新标志
- `aliveKeys`: 页面缓存键

#### 4.2.2 User Store (`src/store/modules/user.ts`)
- `userInfo`: 用户信息
- `tenants`: 租户列表
- `currentTenant`: 当前租户
- `isSuperUser`: 是否超级用户
- 方法：
  - `getUserInfo()`: 获取用户信息
  - `logout()`: 退出登录
  - `selectTenant()`: 切换租户
  - `fetchMyTenants()`: 获取我的租户

#### 4.2.3 Permission Store (`src/store/modules/permission.ts`)
- `accessRoutes`: 可访问路由
- `accessApis`: 可访问 API 权限
- `menus`: 菜单列表
- 方法：
  - `generateRoutes()`: 生成动态路由
  - `getAccessApis()`: 获取 API 权限

#### 4.2.4 Tags Store (`src/store/modules/tags.ts`)
- `tags`: 标签页列表
- `activeTag`: 当前激活标签
- 方法：
  - `addTag()`: 添加标签
  - `removeTag()`: 关闭标签
  - `removeOther()`: 关闭其他
  - `removeLeft()`: 关闭左侧
  - `removeRight()`: 关闭右侧

### 4.3 HTTP 请求封装

**文件**: `src/utils/request.ts`

- 基于 Axios 封装
- 请求拦截器：自动添加 `token` 到请求头
- 响应拦截器：
  - 统一处理错误码
  - 401 自动跳转到登录页
  - 全局错误提示（使用 Ant Design 的 `message`）

### 4.4 权限系统

#### 4.4.1 指令权限
**文件**: `src/directives/permission.ts`

- `v-permission` 指令：根据 API 权限控制元素显示/隐藏
- 超级管理员拥有所有权限

#### 4.4.2 菜单权限
- 动态路由根据后端返回的菜单数据生成
- 无权限页面显示 403

### 4.5 布局系统

**文件**: `src/layout/index.vue`

采用经典的侧边栏 + 顶部栏 + 内容区布局：

- **侧边栏**: `a-layout-sider`，包含 Logo 和菜单
- **顶部栏**: `a-layout-header`，包含面包屑、租户切换、用户信息
- **标签栏**: 多标签页导航
- **内容区**: `a-layout-content`，包含路由视图和过渡动画

## 十一、模板字段同步功能优化

### 11.1 功能概述

模板字段同步功能用于从外部API获取模板列表，通过LLM解析模板内容，自动生成字段组和字段定义。本次优化主要改进了字段填写指引的提取、字段类型默认值设置以及自定义提示词功能。

### 11.2 核心优化点

#### 11.2.1 填写指引（fill_instruction）提取

- **优化内容**: 修改默认提示词，要求LLM返回 `fill_instruction` 字段，整合模板中该字段的所有约束信息
- **提取规范**: fill_instruction 必须包含以下内容：
  - **字段含义**: 该字段代表的业务含义
  - **填写格式**: 如日期格式(YYYY-MM-DD)、手机号格式(11位)等
  - **数据类型**: 字符串、数字、日期、布尔值等
  - **可选范围**: 如是/否选项、特定枚举值
  - **数值标准**: 最小值、最大值、精度要求、单位等
  - **必填要求**: 是否必须填写
  - **示例值**: 从模板中提取的具体示例
  - **特殊规则**: 如只能输入数字、长度限制等

#### 11.2.2 字段类型默认值

- **优化内容**: 不再强制要求LLM解析字段类型，默认将所有字段类型设置为 `text`
- **例外情况**: 仅在模板中明确说明是选择类型（如是/否、多选等）时才使用 `select_single` 或 `select_multi`

#### 11.2.3 自定义提示词功能

- **功能说明**: 支持用户自定义模板解析提示词，控制LLM如何解析模板内容
- **前端实现**: 
  - 在字段编辑页面（`field_spec/index.vue`）添加解析提示词配置区域
  - 使用 `a-textarea` 组件支持多行文本输入
  - 新建字段时自动填充默认提示词，用户无需手动输入即可使用
- **后端实现**:
  - 优先使用字段的自定义提示词（`field_spec.options.parse_prompt`）
  - 其次使用模板配置提示词
  - 最后使用系统默认提示词

#### 11.2.4 命名统一

- **修改内容**: 将 `field_guide` 统一改为 `fill_instruction`，与数据库字段名保持一致
- **涉及文件**:
  - 后端: `app/services/autofill/template_field_service.py`
  - 前端: `frontend/src/views/autofill/field_spec/index.vue`

### 11.3 相关文件

| 文件路径 | 说明 |
|---------|------|
| `app/services/autofill/template_field_service.py` | 模板字段同步核心服务，处理模板解析、字段生成逻辑 |
| `app/schemas/fill_page.py` | 字段选项Schema定义，包含parse_prompt字段 |
| `app/services/autofill/field_spec_service.py` | 字段规格服务，处理字段创建与更新 |
| `frontend/src/views/autofill/field_spec/index.vue` | 前端字段编辑页面，包含解析提示词配置 |

### 11.4 默认提示词示例

```
你是一个专业的模板解析助手。请分析以下模板内容，提取关键信息字段。

## 输入模板内容
{template_content}

## 解析要求
1. 分析模板内容，识别所有需要填写的关键信息点
2. 为每个关键信息提取字段：
   - field_name: 字段英文名（小写，下划线连接）
   - field_label: 字段中文标签
   - field_type: 字段类型（默认为 "text"）
   - fill_instruction: 填写指引（整合所有约束信息）
3. 字段类型说明：
   - 所有字段默认使用 "text" 类型
   - 只有在模板中明确说明是选择类型时才使用 "select_single" 或 "select_multi"

## fill_instruction 填写指引提取规范
fill_instruction 必须整合模板中该字段的所有约束信息，包括但不限于：
1. **字段含义**：该字段代表什么业务含义
2. **填写格式**：如日期格式、手机号格式等
3. **数据类型**：如字符串、数字、日期等
4. **可选范围**：如是/否选项、特定枚举值
5. **数值标准**：如最小值、最大值、单位等
6. **必填要求**：是否必须填写
7. **示例值**：从模板中提取的具体示例
8. **特殊规则**：如只能输入数字、长度限制等

## 输出格式（JSON）
{
    "standard_template": "字段标签: ${field_name}\\n...",
    "fields": [
        {"field_name": "xxx", "field_label": "xxx", "field_type": "text", "fill_instruction": "xxx"}
    ]
}
```
